# 特征评估流程

从一批候选特征里筛出可以进入推荐排序模型的特征，并说明保留、有条件保留或淘汰的理由。

设计细节见 `DESIGN.md`，执行约束见 `RULE.md`，验收用例见 `TEST.md`。

## 环境

Python 3.11。在题目目录安装依赖：

```bash
pip install -r requirements.txt
```

## 启动

在本目录执行：

```bash
python -m feature_eval --data-dir . --config config.yaml
```

`--data-dir` 是三张输入 CSV 所在目录。`--output-dir` 可选，默认写到数据目录下的 `output/`。

## 输出

| 文件 | 内容 |
|---|---|
| `output/report.md` | 可读报告：指标、阈值、三类名单、每个特征的理由、数据质量和复现命令 |
| `output/feature_evaluation.csv` | 每个特征一行，含指标、规则编号、决策和动作 |
| `output/feature_redundancy.csv` | 相关绝对值达到 0.70 的同类型特征对 |
| `output/validation_warnings.csv` | 行数、类型、摘要 AUC 与采样的对照 |

规则测试：

```bash
python -m unittest tests.test_decision -v
```

## 指标体系

五组指标都要算，不能只看摘要里的 AUC。

| 维度 | 看什么 | 为什么 |
|---|---|---|
| 完整性 | 缺失率 | 大面积缺失的特征无法稳定入模 |
| 合法性 | 业务区间、哨兵值、低端截断 | 质量分、粉丝数里有 999999 一类脏值，会把均值和 AUC 拉歪 |
| 区分度 | 数值用有效 AUC，类别用 IV | 有效 AUC = max(AUC, 1-AUC)，活跃间隔、新鲜度这种反向特征仍可用 |
| 可用性 | 唯一值个数、头部覆盖 | 细粒度标签有几千个取值，不能直接入模 |
| 冗余 | 数值 Spearman，类别 Cramér's V | 两个几乎一样的特征只留更强的一个 |

采样是计算来源，`feature_stats.csv` 只做对照。类别 IV 会把不足 30 条样本的取值并入 `__other__`。只有 0/1 两个取值的类别（如付费标识）同时算 IV 和 AUC，取更严的一档。

## 淘汰逻辑

优先级是 `drop` > `conditional_keep` > `keep`。阈值都在 `config.yaml`，不写进代码。

淘汰：缺失率 ≥ 50%，近似常量，决策 AUC < 0.53，IV < 0.02，类别唯一值 ≥ 1000 或 Top5 覆盖 < 5%，哨兵加越界 ≥ 5%，与更强特征相关 ≥ 0.90，描述表有列但采样没有。

有条件保留：方向相反但有效 AUC 达标、少量哨兵需要清洗、弱信号、类别需要编码、中等缺失要加缺失指示、低端截断。直接保留必须跨过保留线，且没有这些附加动作。

已因缺失、无信号或基数淘汰的特征，不能再拿去淘汰别人。

## 关键设计决策

1. 用有效 AUC 做决策。原始 AUC 低于 0.5 只说明方向相反，报告里同时给出原始值、有效值和方向。
2. 先去掉哨兵和越界值，再算 AUC。少量脏值要求清洗，不直接淘汰；清洗后仍然没有区分度才淘汰。
3. 换一批特征只改三张表和 `config.yaml`。评估代码里没有这 15 个特征名的分支。
4. 缺配置项会直接退出，不会悄悄用另一个默认阈值。

## 本次数据的结论

正样本占比 15.54%，采样 40000 行，与摘要一致。同类型特征的相关都低于 0.70，没有因为冗余淘汰。

| 决策 | 特征 | 原因 |
|---|---|---|
| 保留 | `item_ctr_7d`、`user_click_rate_7d`、`cross_user_item_match` | 无缺失，AUC 0.63 / 0.61 / 0.60 |
| 有条件保留 | `user_last_active_gap`、`item_freshness_hour` | 原始 AUC 0.40、0.42，有效 AUC 0.60、0.58，按负向使用 |
| 有条件保留 | `item_quality_score` | 约 0.99% 为哨兵 999999，剔除后 AUC 0.56，入模前要清洗 |
| 有条件保留 | `user_duration_avg_7d` | AUC 0.56，但 26.74% 的值堆在 1 秒 |
| 有条件保留 | `user_pay_flag` | AUC 0.55 刚过保留线，IV 0.068 仍是弱信号 |
| 有条件保留 | `user_city_level`、`item_category`、`user_device_brand` | IV 在 0.03 到 0.07，弱信号，建议消融 |
| 有条件保留 | `user_interest_tag` | IV 0.026，且有 198 个取值，需要编码 |
| 淘汰 | `user_realtime_intention` | 缺失 80.06%，非空部分有效 AUC 也只有 0.51 |
| 淘汰 | `item_author_fans` | 剔除 9999999 后有效 AUC 0.50；约 1% 哨兵和大量 0 改变不了无信号 |
| 淘汰 | `item_tag` | 4836 个取值，Top5 只覆盖 2.69% |

实时意图的「是否缺失」本身 AUC 为 0.28（反向后约 0.72），说明缺失模式和标签有关。缺失率已经到 80%，这个指示不能把特征留在模型里。

完整数字和每个特征的规则编号以 `output/report.md` 为准。
